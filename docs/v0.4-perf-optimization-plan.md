# dsh-dev-plan-presets v0.4.0 全局提速与工程优化开发文档

> **文档定位**：可直接交给快速执行模型（如 Gemini 4 Hydrogen）按步骤落地的自足开发与验收规格书。  
> **目标版本**：`0.4.0`（基于当前 `0.3.0` 基线，`56/56` 单测全绿）  
> **核心痛点**：对话干活流程慢、主窗思考/打字久、子代理冷启动与往返多、设置页存在无效轮询与首屏延迟。  
> **不可突破的插件理念（红线）**：
> 1. 昂贵主模型的核心定位仍是 **规划、派工、复核与决策**，绝不放任主模型把额度烧在大仓库遍历、反复试错跑命令或大段写代码上；
> 2. 所有委派子代理继续钉死在便宜模型（`modelGuardMode=pin`，默认仅守 `dev-plan` 父会话的子代理，**主会话永不被守门改模型**）；
> 3. **派工事实**（仅实际 `develop` / `send_message` 工具调用算派工，文本不算）、**事实归属**（不把子代理自述当自己跑过测试）、**证据化审查**、**用户授权边界** 一条不退；
> 4. **运行期零 `dependencies`**，不 import `js-yaml` 或 `@deepseek-ai/*`，不修改 profile 文件，不引入重型调度器/DAG。

## 二、架构设计总览（五个正交模块）

本次优化分为 **5 个解耦的工作包（WP1 ~ WP5）**，按依赖顺序逐个实现并验证。

### WP1：受控的主窗轻实操能力（可配置，默认极克制）

#### 设计结论与理念守恒
针对“主模型希望偶尔直接用一点工具做小查证或微改动，但必须经过用户同意、避免烧额度”的需求，不能无约束把 Shell/写工具塞给主窗，而是新增一个显式设置项 `mainToolMode`（三档枚举）：

| 档位值 | 名称 | 主窗额外挂载的插件 | 核心规则与防烧额度机制 | 适用人群 |
|---|---|---|---|---|
| `'none'`（**默认**） | 纯规划派工 | 无（与 0.3.0 完全一致） | 自身永不直接读/写/跑命令，100% 保持原教旨 | 极度省主模型额度、严格分工 |
| `'readonly'` | 定点只读核验 | 仅挂载 `@deepseek-ai/dsh-tool-fs-search`（`glob` / `grep`） | 允许主窗直接做极小范围的文件定位/符号搜索，**仍无写入和 Shell 能力**；大仓库遍历仍交 `recon` | 希望消除“找个文件/搜个符号也要等子代理”的卡顿，零误改风险 |
| `'ask-edit'` | 授权微实操 | 挂载 `@deepseek-ai/dsh-tool-fs`（`applyPatch: false`）+ `@deepseek-ai/dsh-tool-fs-search`；**永远不挂 `bash`/`pwsh`/`workflow`/`jobs`/`schedule`** | 1. **只读核验**（`read`/`glob`/`grep`）限小范围定点核对（≤ 3 个文件 / 看一眼关键片段），大面积扫描仍交 `recon`；<br>2. **任何写/改（`write`/`edit`）必须先获用户本轮明确同意“主窗直接改”**，单次同意仅限 **≤ 2 个文件、局部小改（约 ≤ 50 行）**；<br>3. **绝不跑 Shell/测试命令**（无 Shell 工具），需要跑测试/大改仍交 `develop`；<br>4. **Host 层步数软闸门**（见下）：连续实操步数超过阈值时自动向主会话注入一次额度告警，防止主模型陷入自嗨循环 | 既想主窗秒查文件/在同意后秒改几行小 bug，又不想主模型失控烧额度 |

> **为什么不挂 `bash`/`pwsh` 给主窗？**  
> Shell 命令是主模型烧额度最快、最不可控的源头（跑测试失败 → 读报错 → 改代码 → 再跑测试的死循环）。把 Shell 与构建/测试永远留在便宜的 `develop` 子代理侧，能从机制上守住 90% 的额度防线。

> **为什么默认仍是 `'none'`？**  
> 保证升级兼容与零意外：现有用户配置升级到 0.4.0 后行为与原理念完全一致；想提速的用户在设置页一键切到 `'readonly'` 或 `'ask-edit'` 即可生效（新会话生效）。

#### Host 层防烧额度保护（配合 `'readonly'` / `'ask-edit'`）
- 在 `settings.js` 新增：
  - `MAIN_TOOL_MODES = Object.freeze(['none', 'readonly', 'ask-edit'])`
  - `mainToolMode: 'none'`（默认值）
  - `mainStepWarnThreshold: 6`（整数，范围 `2..30`，默认 `6`：仅在 `mainToolMode !== 'none'` 时对 `dev-plan` 主会话生效；单轮用户回合内主窗连续走过超过阈值步的 LLM step 时，通过 `agent.inject()` 或日志提示“当前主模型已连续执行较多步骤，建议将后续探索/修改转交 `recon` 或 `develop` 以节省主模型额度”，**绝不 `cancel` 主会话，绝不修改主会话模型**）。
- **重要边界**：主会话的“额度步数提醒”必须独立于 `modelGuardMode` 的子代理守门，且：
  - **永不调用 `agent.model.select()`**；
  - **永不 `reject` 或 `cancel` 主会话**（只做温和提醒，每轮最多提醒 1 次，下一轮用户消息重置计数，避免刷屏）。

### WP2：干掉主模型手抄 1,125 字模板 & 轻量化子代理（最大提速点）

#### 核心改造：用轻量内置子 preset 替代 `standard` + 逐字手抄模板

当前 `recon` / `review` / `scribe` 每次调用慢 15~25 秒，根因是它们挂了沉重的 `standard` 且靠主模型把 1,125 / 888 字模板抄进 `prompt`。

**架构方案（双保险，100% 仅依赖已验证的 `ctx.agentPresets.register()` API）**：

1. **在 `preset.js` 新增两个轻量内置子预设构造器**（纯函数，零外部依赖）：
   - `SCOUT_PRESET_ID = 'dev-plan-scout'`（供 `recon` 与 `review` 使用）
     - `order: 990`（排在预设列表最底，不干扰主预设；若未来宿主支持 `hidden: true` 可透传 `hidden: true`，但不得依赖它）
     - `name: '开发规划 · 内部侦察/复核（勿直选）'`
     - `description: 'dev-plan 内部轻量子代理：仅挂载只读文件/搜索/网页工具，内置只读与证据输出契约。'`
     - **极简插件清单**（相比 `standard` 砍掉 bash/pwsh/workflow/jobs/schedule/goal/skill/todo/present/subagent/plan-mode 十几个插件）：
       - `@deepseek-ai/dsh-persona`（直接内置精简后的只读侦察/复核 persona，~450 字！）
       - `@deepseek-ai/dsh-agent-instructions`（`maxBytes: 32768`，减半）
       - `@deepseek-ai/dsh-compaction-basic` + `@deepseek-ai/dsh-compaction-tool-result-pruner`（`thresholdChars: 12288, headChars: 6144, tailChars: 1536`）
       - `@deepseek-ai/dsh-tool-fs`（`applyPatch: false` — 提供 `read`/`read_image`，persona 声明禁止 `write`/`edit`）
       - `@deepseek-ai/dsh-tool-fs-search`（`glob`/`grep`）
       - `@deepseek-ai/dsh-tool-web`（`web_search`/`web_fetch`）
   - `SCRIBE_PRESET_ID = 'dev-plan-scribe'`（供 `scribe` 使用）
     - `order: 991`
     - `name: '开发规划 · 内部文书（勿直选）'`
     - `description: 'dev-plan 内部轻量子代理：仅挂载文件工具，只负责把定稿文档逐字落盘。'`
     - **极简插件清单**：
       - `@deepseek-ai/dsh-persona`（直接内置精简后的文书落盘 persona，~350 字！）
       - `@deepseek-ai/dsh-compaction-basic`
       - `@deepseek-ai/dsh-tool-fs`（`applyPatch: false` — 提供 `read`/`write`/`edit`）

2. **在 `index.js` 中一起注册 & 清理**：
   - 在 `publish()` 中先注册 `dev-plan-scout` 和 `dev-plan-scribe`（各自收集 disposer），再注册 `dev-plan`；
   - **回退安全网**：如果某内部子 preset 注册失败（例如宿主禁止注册多 preset 或抛异常），自动降级让 `recon`/`review`/`scribe` 回退到 `standard`，并在 `state.warnings` 里显式记录，**绝不导致主 preset 注册失败**；
   - `dev-plan` 里的 `resolveDevelopMode` 和设置页 `presetChoices` 自动禁用内部预设（`selfIds = ['dev-plan', 'dev-plan-scout', 'dev-plan-scribe']`），防止用户误选内部只读预设作为 `developMode`！
   - `dispose()` 时按逆序释放所有注册返回的 disposer。

3. **彻底取消主模型手抄模板**：
   - 当内部轻量子预设注册成功时，`dev-plan` 主窗的 `recon` / `review` 绑定 `agentPreset: 'dev-plan-scout'`，`scribe` 绑定 `agentPreset: 'dev-plan-scribe'`；
   - 主窗 persona **不再包含 2,013 字的 `SCOUT_TEMPLATE` / `SCRIBE_TEMPLATE` 全文**，主模型调用 `recon` / `review` / `scribe` 时**只需直接写简洁的任务与输出要求**，彻底省掉每次 **15~25 秒** 的模板抄写时间与几百个昂贵 output tokens！
   - 若降级回 `standard`（极端异常），`buildPersona` 会附带精简版提示（≤ 250 字）兜底。

> **关于 `preset.js` 导出的向后兼容**：继续导出精简后的 `SCOUT_TEMPLATE` 与 `SCRIBE_TEMPLATE` 常量（用于内置子预设 persona 和单测），不再在正常模式下把它们拼进主窗 `prefix`。

### WP3：主窗 Persona 瘦身 55%+ & 协作协议提速（消除“三遍文档”与冷启动）

#### 硬量化指标
- 主窗 `persona.prefix + persona.suffix` 总字符数从 **12,648 字符** 压缩到 **≤ 5,500 字符**（目标 **4,500 ~ 5,200 字符**，减少 **55%~60%**）。
- **零信息丢失原则**：每条硬规则只在一处权威位置写清（SSOT），禁止跨章节重复粘贴 4~6 遍。

#### 具体精简与提速规则（写入 `preset.js` 的 `buildPersona`）

1. **合并“三遍文档”为“单契约复用”**：
   - **快速路径**（范围清楚、单/少量文件、可回滚、验证明确）：
     - 规划阶段只输出 **极简计划（≤ 15 行）**：路径判断、改动文件、验收命令、非目标，直接问一句“确认开工？”；
     - 获批后直接把这份精简契约作为 `develop` 的 `prompt` 发出，**不再扩写成 10 段官样文章**。
   - **标准 / 高风险路径**：
     - 规划阶段输出的「开工契约」与 `develop` 任务书采用 **同一套 8 字段紧凑结构**（目标 / 非目标 / 允许路径 / 接口约束 / 验收标准 / 检查命令 / 风险回退 / 变更证据与汇报要求），开工时直接带工作区绝对路径与 `cwd` 发给 `develop`，无需重写第二遍。
   - **禁止废话**：规划阶段不需要写背景长文、方案散文；直给结论、取舍表与契约。

2. **引入 `recon` 复用与并发纪律**：
   - 同一任务的持续取证，首次固定 `name=scout`，后续补充查证优先用 `send_message` 续问同一个 `scout`（保留已读上下文，避免反复冷启动）；
   - 遇到 2~3 个互不依赖的模块查证时，允许主窗**单回合并行**调用多个 `recon`（命名 `scout-1`、`scout-2`），用并发换串行等待。

3. **修复 `tool-result-pruner` 与 Diff 交付策略的矛盾**：
   - 在 `preset.js` 中，将主窗的 `tool-result-pruner` 配置从 `{ thresholdChars: 8192, headChars: 4096, tailChars: 1024 }` 调整为：
     `{ thresholdChars: 24576, headChars: 16384, tailChars: 4096 }`；
   - 在 `develop` 汇报契约中明确**分层变更证据**：
     - 改动 ≤ 200 行：直接附真实 `git diff`（或新文件关键内容）；
     - 改动 > 200 行：附 `git diff --stat` + 关键逻辑变更的真实 hunks + 完整 diff 导出位置/命令，避免灌爆主窗上下文或被截断引发二次补证据往返；
   - 仍坚守红线：只有文件清单/口头摘要不算审过 diff，必须先 `send_message` 让同一 `developer` 补真实变更证据。

4. **保留的全部核心合同清单（必须在新版精简 persona 中 100% 明确保留）**：
   - 角色定位与 `mainToolMode` 对应的工具纪律（`none`：永不亲自写代码/不调未声明工具；`readonly`：仅允许小范围 `glob`/`grep` 定点核验；`ask-edit`：仅在用户当轮明确同意后允许 ≤ 2 文件 / ≤ 50 行的局部微改，永不跑 Shell）；
   - 施工目录与权限红线：调 `develop` 必须传 `cwd` 参数、派工前核对可写范围、不得先建后 `cd`、父会话事后提权不扩大已有子代理权限、权限失败如实记录 `cwd`/沙箱/原错并停止重试；
   - 派工事实红线：文本不是派工，必须实际调用 `develop`（首次 `name=developer`）并收到接受结果后才可说“已派出 developer”，之后结束回合等自动完成通知；返工必须实际调用 `send_message`；失败/未调用必须如实报“未派工”及原因；
   - 双通道互斥：同一任务不得混用 `develop` 与 `rework_task` / `ask_worker`；
   - P0 五条完整保留（精炼表达）：
     - P0-1 风险分级（快速/标准/高风险；四维：歧义、影响面、可逆性、可验证性；绝不因验证困难降级；快速路径不取消用户批准、developer 自验、主窗审查）；
     - P0-2 一次性开工契约（批准一次覆盖已批准范围；普通实现不反复请示；仅范围扩大/风险变化/宿主权限要求重新确认）；
     - P0-3 验收前置与成本排序（最小切片 → 语法/静态契约 → 针对性测试 → 必要运行/GUI 验收；静态检查不等于真实验证）；
     - P0-4 非阻塞协作（依赖自动通知，不轮询、不忙等、不重复施工、不重复读 developer 正在改的文件；developer 仅在阻塞/范围冲突/关键契约决策时打断）；
     - P0-5 证据化审查与严重度返工（汇报标 `verified` / `partial` / `failed` / `未验证`；按阻塞/重要/建议审查；阻塞续派同一 developer，非阻塞不无限打磨；主窗最终审查责任不外包）；
   - 事实归属（`suffix`）：不把子代理自述当自己跑过测试，引用写明“按 developer 汇报”；无工具调用接受不得声称已派出/已返工/已验证；无实际 diff/等价证据只算摘要审查。
   - 禁止在 persona 中写 `{{...}}` 模板变量。

### WP4：Host 与 Client 运行时工程去卡顿

#### 4.1 `index.js` 优化清单
1. **引入单调状态版本号 `stateVersion`**：
   - 任何写入 `state`、`violations`、`warnings`、`modelCatalog` 的地方调用 `bumpState()`（`stateVersion += 1`）；
   - `GET /plugins/dev-plan-presets/state` 响应新增 `stateVersion` 字段，同时支持 `If-None-Match: "<stateVersion>"`（命中返回 `304 Not Modified`，零 JSON 序列化、零响应体），响应头带 `etag: "<stateVersion>"`。
2. **缓存不可变派生值**：
   - `const cachedRoute = routeOf(settings)` 在 `apply()` 初始化时算一次，不再每次 `buildState()` 重跑 `normalizeSettings()`。
3. **修复 `scheduleVerification()` 冗余二次全量探测**：
   - `index.js:387` 原条件：
     `const needsRecheck = settings.developMode !== 'standard' || state.presets.checked !== true`
   - 改为：
     `const needsRecheck = state.mode?.fallback === true || state.presets.checked !== true`
   - 效果：首次探测已成功找到目标 preset（如 `deep-ptc`）时，不再在 2s 后白跑第二次 `registry.list()`。
4. **空闲预热 `modelCatalog`**：
   - 在 `webServer` 路由注册完成后，用 `setTimeout(() => void refreshModelCatalog(), 300)`（并 `.unref()`，且在 `effect` 卸载时 `clearTimeout`）提前在后台预热一次模型目录；
